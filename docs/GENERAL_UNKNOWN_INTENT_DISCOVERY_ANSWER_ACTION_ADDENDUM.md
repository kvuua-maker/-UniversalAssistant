# General Unknown-Intent Discovery / Answer / Action Fallback

Canonical owner addendum accepted 2026-09-03. It supplements Master Spec v13.2 and every accepted addendum. UniversalAssistant is a universal action/discovery assistant, not a finite menu of hardcoded commands.

## Routing contract

Every request follows this order: (1) exact existing production capability; (2) general deterministic typed discovery; (3) one bounded, optional, cancellable, privacy-filtered AI interpretation/synthesis only for residual complexity; (4) exactly one useful clarification for material ambiguity; (5) a precise truthful limitation only when evidence, permission, account, provider, safety or law prevents help. Generic routing never displaces a better specialized capability and AI never supplies live facts.

## Generic semantic contract

The provider-neutral typed core represents extensible domain/category, subject/entity, goal, location, date/time window, monetary minimum/maximum and currency, quantity, distance, duration, quality/rating, brand/provider, include/exclude constraints, sorting, required freshness, requested action and risk. Optional typed fields remain optional; extensibility metadata is bounded and validated rather than an unrestricted dictionary.

## Discovery and truth

Unknown safe requests may create a minimal search plan, query independent sources concurrently, classify source quality by domain, prefer authoritative primary/official/government/authorized sources, retrieve bounded lawful HTTPS content, extract structured metadata/JSON-LD/feeds/API/semantic HTML or bounded page facts, retain per-fact source/retrieval time/confidence/original semantics, resolve conflicts by domain quality and freshness, deduplicate without merging genuine variants, and compose a native result. Search snippets never prove critical/live values. Missing, blocked, CAPTCHA, login, dynamic-only, stale or conflicting data remains unknown/uncertain rather than absent, free, unavailable or current.

## Results, action and safety

Generic cards use reusable native presentation: optional image/icon, title, verified primary/secondary facts, price/status/date/location when known, source/freshness and one truthful action. Labels reflect capability: Open/View/Navigate/Call/Email/Apply/Book/Buy/Contact/Save/Share only when the corresponding path exists. An open-only vacancy is “Open vacancy”, never “Applied”; a product handoff is not checkout. Informational discovery may run directly. Consequential or unknown actions pass existing typed permission/confirmation gates and fail closed; generic interpretation creates no side-effect path.

## Context, privacy, cache and failure

Relative location/time reuses fresh approved context and asks only for missing material context. Approved preferences may rank but never invent or hide facts. External queries contain only minimal necessary data and exclude raw contacts, email/calendar content, precise location, identity and loyalty data unless specifically permitted and required. Cache identity includes meaningful city/date/budget/role/variant/user constraints and uses domain-appropriate freshness. Partial provider success returns honest useful partial results; total failure returns retry/handoff/“no trustworthy current results”. No uncontrolled self-modification is allowed; permanent providers/capabilities require controlled configuration/update.

## Required acceptance

Executable production-path evidence must cover: job role/location/minimum salary; local repair; budget course; authoritative factual answer; dated events; specialized-capability precedence; deterministic no-AI unknown handling; exactly one bounded AI case and AI-unavailable fallback; one clarification; partial/all-source failure; conflict/stale/blocked/CAPTCHA/snippet conflict; dedup and variants; open-only action; consequential confirmation; relative location/time; cache separation; privacy-minimized query; live value remains unknown; and an unknown supported domain never receives “function unsupported”. Golden journeys cover job, repair, course, events, current commodity/service price, general factual timing, ambiguity, deterministic solution, bounded synthesis and no trustworthy answer.

Completion requires the full chain: unknown request → semantic structure → discovery → retrieval → extraction → provenance/freshness → native composition → truthful action → safety/failure. A browser URL, `unknown` enum or AI interface alone is insufficient.
