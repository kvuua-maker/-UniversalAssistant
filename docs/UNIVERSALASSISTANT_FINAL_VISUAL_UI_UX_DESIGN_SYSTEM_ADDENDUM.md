## 1–4. Canon and identity

Visual priority is: this textual canon; the last wide system mockup as structural reference; the two iPhone purple/blue orb mockups as primary voice-orb reference; the dark call→listen→result→detail→action→done storyboards as flow reference; older mockups only for non-conflicting confirmed details. Never mix alternatives or invent an averaged style.

The product is a premium, calm, minimal, Apple-native universal interface to internet, services, iPhone and actions—not a chat, browser, search page, dashboard, admin panel or AI demo. Default identity is a nearly black blue-black theme with a restrained luminous purple/electric-blue orb. Optional coherent accents: purple, blue, cyan, green, amber/orange, pink. Avoid neon/cyberpunk excess.

The large central microphone orb is the primary voice element. Typed states: IDLE (calm), LISTENING (responsive breathing/waveform and short “Слухаю…”), PROCESSING (smooth, no technical checklist), SUCCESS (brief check), ERROR/NEEDS_INPUT (clear, non-aggressive). Results displace the orb when content becomes primary.

## 5–10. Home, input and output

Home contains branding, short mode/status, central orb/microphone, short context, unobtrusive “Або напишіть” input, and minimal menu/settings navigation. Voice is primary and text secondary; category navigation is secondary discovery, never a required pre-routing step. Default UI is not a messenger transcript.

Voice input and output are separate. Do not automatically read long informational results. Speak only for active voice/hands-free/navigation, explicit say/read requests, short critical warnings, or when screen is not primary. Preference is typed/configurable/persistent. Do not needlessly duplicate long voice and screen output.

Global rule: DO, DON'T NARRATE. Clear allowed actions execute without “found/opening/now doing” narration. Important completed actions may use one compact factual confirmation: “Збережено”, “Записано”, “Заброньовано”, “Надіслано”, “Готово”. Short operations need no ceremonial processing screen; longer work may show only human-useful progress. Native structured results are primary; web handoff is a controlled fallback/final provider action, never visible browser chrome or a search-results aesthetic.

## 11–21. Native result grammar

Reusable typed cards use this hierarchy: useful image; title; key attributes; verified price/status/availability; source/provider; one clear primary action; only necessary secondary actions. Never expose API/provider routing/logs/URLs/JSON/AI chains. CTA semantics must match capability—never show Buy or confirmed booking when only handoff exists.

Product cards show image, brand/description, relevant variants, verified price/availability/source and truthful buy/product handoff; sponsored status is explicit and affiliate attribution unobtrusive. Place/restaurant cards show image, name, rating/distance/cuisine/price level/open state and confirmed availability only; detail adds useful verified facts and booking only when supported. Hotel/travel/transport cards use the same grammar with origin/destination/times/duration/availability/price/provider and practical ranked reasons, not an AI essay. Housing, vehicles, appointments/services, parcels and documents use domain-appropriate verified facts and one truthful action. Parcel precision/ETA and booking state are never fabricated. Scanner is camera-first with document frame, large capture control and minimal controls; document/PDF workflows remain native rather than desktop-editor replicas.

History is secondary and privacy-safe: compact action, target/detail, time and status without prohibited raw commands. Trivial actions do not receive celebration screens or unnecessary modals.

## 22–36. Settings, themes and structure

Settings remain understandable and group AI/Mode, Language, Appearance, Voice & interaction, Permissions, Profile/account, Connected accounts, Subscription/plan, Personalization, Notifications, Privacy & data, and About. Technical controls never dominate. AI is optional, default off unless explicitly connected, truthfully shows provider/connection/usage, and is never the visual identity. Plans show only real limits without urgency or main-screen clutter.

One design system supports Automatic/System (default), Dark and Light. Light preserves identical information architecture with off-white surfaces, readable dark text, restrained accents and subtle borders/shadows. Dark uses near-black background, distinguishable elevated cards, restrained borders and purple/blue highlights without crushed blacks or ubiquitous glow. Accent affects orb, primary CTA, selected controls and highlights—not every surface.

Use SF typography, Dynamic Type, generous spacing and few primary controls. Normal result flow needs one or two interactions. Navigation preserves fast Home, ongoing/personal tasks, saved/favorites and history/profile semantics without copying contradictory screenshots or making every domain a tab. Secondary menu exposes only supported recent/frequent, housing, food, shopping, transport, entertainment, services, documents, tasks/cases and history domains. Maps appear only when spatially useful and do not unnecessarily precede lists.

Errors are human-readable and truthful. Partial provider success remains usable; unknown stays unknown; handoff is labeled as handoff. Informational, reversible and consequential actions are visually distinguishable, with confirmation only where canonical safety requires it. Presentation preferences may persist but never alter facts or core behavior.

## 37–47. Motion, accessibility and reusable UI

Animation communicates orb state; other transitions are fast/subtle. Respect Reduce Motion and provide reduced animation. Haptics are restrained and system-appropriate for significant activation/completion only. Required accessibility: Dynamic Type, VoiceOver labels, sufficient contrast, large targets, Reduce Motion, no color-only state, meaningful orb/microphone/action names, and dark/light verification. Accessibility outranks screenshot fidelity.

All supported languages retain layout integrity with no Ukrainian/English fixed-width assumptions or clipped longer German/French/Russian labels. Layout adapts across supported iPhones and appropriate iPad presentation without hardcoding one screenshot or Dynamic Island model.

“Browser-like” means request→structured data→native cards/page→action, with no address bar, tabs, browser chrome or SERP. Speed is part of design: no unnecessary screens, transitions, repeated confirmations, tutorials or typing; show first useful truthful result promptly. Simple paths never wait for AI or display fake AI thinking. Beauty never permits fabricated price, availability, slot, ETA, rating, stock, confirmation or route state.

B2B/affiliate infrastructure does not create an admin-looking consumer UI. Sponsored content is disclosed within the same system. Use reusable typed product, place, travel, appointment, document, parcel and confirmation cards; provider-specific UI exists only for genuine semantic differences.
